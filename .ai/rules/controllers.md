# Controllers

## Public endpoints must read the viewer from the sanctum guard
Public read endpoints (events, rounds, games) carry no auth middleware, so `$request->user()` resolves the `web` guard and is null for token clients. Use `$request->user('sanctum')` when a public endpoint needs to know who is looking — e.g. showing Draft Rounds to Organisers. `Event::isOrganisedBy()` accepts null for exactly this. `actingAs()` in tests still works, because Sanctum's guard falls back to the web guard when there is no bearer token.

## A Draft or Cancelled Event is gated by Event::isVisibleTo(), and answers 404
Whether a reader may see an Event at all is `$event->isVisibleTo($request->user('sanctum'))`: public statuses for everyone, Draft and Cancelled for its Organisers only. Abort 404, never 403 — a 403 confirms the Event exists. It is deliberately not a policy ability (a policy denies with 403 and would start gating Filament's View action), it costs no query while the Event is public, and Admins get no bypass. Every read of a single Event and what hangs off it goes through it; do not reach for `$event->status->isPubliclyVisible()` by hand. Public reads (pulse, factions, schedule, standings, attendees, games, updates, gallery, polls and their candidates) use it as their only gate. Organiser-only reads (score types, organisers, flags, poll results, feedback and its export) call it *before* `Gate::authorize('organise')`, so a stranger gets 404 rather than a 403 that confirms the Event exists. Rounds have a rule of their own, `Event::hasRoundsVisibleTo(?User)`: everyone once the Event is under way (Active, Completed), its Organisers always, a guest accepted and no query when the status already allows it. The Rounds list, Round detail and My game use it. Submitting and flagging a result keep the status-only `EventStatus::hasRoundsVisible()` on purpose — seeing pairings early is not playing them, and an Organiser playing in their own Event waits like everyone else. A new public read gets two tests over the `hidden event statuses` dataset: `coOrganiserOf($event)` reads it, and `playerOf($event)` still gets 404. A new Organiser-only read gets the second.

## Regenerate docs/openapi.yaml with composer docs, never by hand
`docs/openapi.yaml` is generated by `composer docs` (`php artisan docs:spec`). CI reruns it and fails when the diff is non-empty. After any endpoint or Scribe attribute change, run `composer docs`, then `npm run types:generate` in `frontend/`, and commit both files. Do not hand-edit the spec to match a sibling entry: Scribe's output differs, for example a 204 with no body becomes nullable `application/json`, not `text/plain`. Do not commit the `.scribe/` or `resources/views/scribe` churn it leaves behind. Those files carry factory ids and timestamps that change on every run.
