# Controllers

## Public endpoints must read the viewer from the sanctum guard
Public read endpoints (events, rounds, games) carry no auth middleware, so `$request->user()` resolves the `web` guard and is null for token clients. Use `$request->user('sanctum')` when a public endpoint needs to know who is looking — e.g. showing Draft Rounds to Organisers. `Event::isOrganisedBy()` accepts null for exactly this. `actingAs()` in tests still works, because Sanctum's guard falls back to the web guard when there is no bearer token.

## A Draft or Cancelled Event is gated by Event::isVisibleTo(), and answers 404
Whether a reader may see an Event at all is `$event->isVisibleTo($request->user('sanctum'))`: public statuses for everyone, Draft and Cancelled for its Organisers only. Abort 404, never 403 — a 403 confirms the Event exists. It is deliberately not a policy ability (a policy denies with 403 and would start gating Filament's View action), it costs no query while the Event is public, and Admins get no bypass. Do not reach for `$event->status->isPubliclyVisible()` alone on a screen an Organiser must be able to open.

## Regenerate docs/openapi.yaml with composer docs, never by hand
`docs/openapi.yaml` is generated by `composer docs` (`php artisan docs:spec`). CI reruns it and fails when the diff is non-empty. After any endpoint or Scribe attribute change, run `composer docs`, then `npm run types:generate` in `frontend/`, and commit both files. Do not hand-edit the spec to match a sibling entry: Scribe's output differs, for example a 204 with no body becomes nullable `application/json`, not `text/plain`. Do not commit the `.scribe/` or `resources/views/scribe` churn it leaves behind. Those files carry factory ids and timestamps that change on every run.
